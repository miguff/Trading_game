# Quickstart Validation Guide

**Date**: 2026-06-11
**Feature**: Energy Trading Game - Day 1 MVP
**Spec**: `specs/001-energy-trading-mvp/spec.md`
**Plan**: `specs/001-energy-trading-mvp/plan.md`

## Prerequisites

- Python 3.11+
- Modern web browser (Chrome/Firefox/Edge) with 1280px+ width
- `requirements.txt` installed: `pip install -r requirements.txt`

## Start the Application

```bash
# From repository root
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

The application will be available at `http://localhost:8000`.

## Validation Scenarios

### Scenario 1: Player Join and Role Assignment (US1)

**Goal**: Verify players can join and receive correct roles in round-robin order.

**Steps**:
1. Open `http://localhost:8000` in Browser Tab 1
2. Enter name "Alice" and click Join
3. Verify: Alice receives role "Generator"
4. Open `http://localhost:8000` in Browser Tab 2
5. Enter name "Bob" and click Join
6. Verify: Bob receives role "Retailer"
7. Open `http://localhost:8000` in Browser Tab 3
8. Enter name "Carol" and click Join
9. Verify: Carol receives role "Trader"
10. Open `http://localhost:8000` in Browser Tab 4
11. Enter name "Dave" and click Join
12. Verify: Dave receives role "Generator" (cycle repeats)

**Expected**: Each player sees their assigned role on the join confirmation screen.

---

### Scenario 2: Admin Starts Round (US2)

**Goal**: Verify admin can start rounds and players receive news.

**Steps**:
1. Open `http://localhost:8000/admin` in a separate browser window
2. Select scenario "up" from the dropdown
3. Click "Start Round"
4. Verify: All player tabs receive a "Round Started" notification with round number, scenario, and news text
5. Verify: Player screens switch from lobby to trading interface
6. Verify: Countdown timer appears and counts down from 90 seconds

**Expected**: All connected clients synchronously receive round start state.

---

### Scenario 3: Trading and P&L Updates (US3)

**Goal**: Verify buy/sell execution, position updates, and live P&L calculation.

**Prerequisites**: Round is active with at least one Generator player.

**Steps**:
1. As Generator (Alice), observe the dashboard shows:
   - Position: "+10 MWh"
   - Cash: 0 EUR
   - Expected Cash: -475 EUR (at start_price=50)
   - P&L: +25 EUR
   - Cost Basis: 47.50 €/MWh
   - Break-Even: 47.50 €/MWh
   - Status: "In profit zone"

2. Click "Sell" button once
3. Verify:
   - Position changes to "+9 MWh"
   - Cash increases by bid price
   - P&L updates using current mid-price
   - Break-even price recalculates

4. Click "Buy" button once
5. Verify:
   - Position changes back to "+10 MWh"
   - Cash decreases by offer price
   - P&L updates

**Expected**: All values update instantly on each trade. No page refresh required.

---

### Scenario 4: Position Limits (US3)

**Goal**: Verify role-specific position limits are enforced.

**Steps**:
1. As Generator, attempt to sell 11 times in succession (starting from +10)
2. Verify: The 11th sell is rejected with "Position limit exceeded"
3. Verify: Position remains at 0 MWh after 10 sells
4. As Trader, attempt to buy 11 times in succession (starting from 0)
5. Verify: The 11th buy is rejected with "Position limit exceeded"
6. Verify: Position remains at +10 MWh after 10 buys

**Expected**: Server rejects trades that would breach limits without changing state.

---

### Scenario 5: Round End and Leaderboard (US4)

**Goal**: Verify round close-out, cumulative P&L, and leaderboard display.

**Steps**:
1. Let the round timer count down to zero (or wait for 90 seconds)
2. Verify: All clients receive "Round Ended" event
3. Verify: Round summary shows each player's round P&L
4. Verify: Leaderboard ranks players by cumulative P&L
5. Verify: Closing positions carry forward, then the next round adds +10 for Generator, -10 for Retailer, and 0 for Trader
6. Verify: Cash resets to 0 for all roles
7. As admin, click "Start Next Round"
8. Verify: New round starts from previous round's ending price
9. Verify: Price charts continue without reset

**Expected**: Complete round lifecycle with carried positions, per-round allocations, incremental P&L, and final position valuation.

---

### Scenario 6: Stochastic Final Round (FR-08)

**Goal**: Verify the final round continues the market without a forced return to game_start_price.

**Steps**:
1. Configure game for 2 rounds (or play through to final round)
2. Note the `game_start_price` displayed at round 1 start
3. Play through all rounds
4. Observe the final price path and verify the final tick is generated by market movement, not overwritten with `game_start_price`

**Expected**: Final price remains stochastic and is not forced to equal the initial game start price.

---

### Scenario 7: Multi-Player Load Test (SC-001)

**Goal**: Verify 30 simultaneous players can join without issues.

**Steps**:
1. Open 30 browser tabs to `http://localhost:8000`
2. Join with 30 different names
3. Verify: All 30 players receive roles in correct round-robin cycle
4. Start a round
5. Verify: All 30 clients receive round start event within 2 seconds

**Expected**: System handles 30 concurrent connections smoothly.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| WebSocket connection fails | Verify `ws://localhost:8000/ws` is accessible; check firewall |
| Port already in use | Use `--port 8001` or kill existing process |
| Static assets not loading | Verify `static/` directory exists at repo root |
| Session lost on refresh | Rejoin with same name; token persistence is best-effort for MVP |
| Price updates stop | Check server logs; round may have ended |
